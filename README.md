## 논문

> **근거 오염 환경에서 RAG의 응답 강건성과 기권 기반 방어기법에 관한 연구**
> 박정원, 안솔은, 서현우, 이동현, 이규영
> ACK 2026 (한국정보처리학회 추계학술발표대회) · 스마트해운물류×ICT멘토링 학부생 트랙

📄 [논문 전문 (PDF)](논문_RAG근거오염실험/paper/)

### 연구 질문

RAG는 LLM에게 외부 문서를 근거로 쥐여줘 환각을 줄입니다. 그런데 **검색이 엉뚱한 근거를 가져왔을 때**,
모델은 그것을 권위 있는 정보로 믿고 더 확신에 찬 오답을 내지 않을까요?
항만 안전처럼 오답이 사고로 이어지는 도메인에서는 실질적인 문제입니다.

### 결과

**오염의 양은 위험 요인이 아니었습니다.** 정답 조항이 근거에 하나라도 남아 있으면,
같은 문서에서 항목명과 서술 형식이 거의 같고 수치만 다른 조항을 4개까지 주입해도 오답률은 5% 미만이었습니다.
위험은 **정답 근거가 완전히 누락될 때** 발생했습니다.

| 주입된 오염 조항 | 단답 P0 | 단답 P1 | 설명 P0 | 설명 P1 |
|---|---|---|---|---|
| 0 ~ 4개 (정답 근거 있음) | 0 ~ 1.2% | 0 ~ 4.6% | 0 ~ 0.4% | 0.0% |
| 전량 (정답 근거 없음) | **100.0%** | 52.9% | **86.7%** | 25.0% |

*P0 = 기본 지시문 / P1 = 기권 유도 지시문*

기권 유도 프롬프트는 전량 오염 구간에서 오답률을 절반 이하로 낮췄지만,
**줄어든 오답은 정답이 아니라 전부 기권으로 이동**했습니다(단답 47.1%, 설명 75.0%).
정답 근거가 없으면 맞히는 것이 원리상 불가능하므로, 프롬프트가 할 수 있는 최선은
**위험한 실패를 안전한 실패로 바꾸는 것**이고 실제로 그렇게 했습니다.

다만 대가가 있습니다. 검색이 정상인 구간에서는 단답형 정답률이 99.2% → 97.6%로 떨어지고,
설명형은 답할 근거가 있는데도 11.0%가 불필요하게 기권했습니다.
**상시 적용이 아니라 검색 신뢰도가 낮을 때 선택적으로 켜는 안전장치**로 써야 한다는 결론입니다.

### 방법론에서 신경 쓴 것

- **오염을 어렵게 설계했습니다.** 선행 연구는 주제가 무관한 문서를 노이즈로 쓰지만,
  이 연구는 같은 문서 안에서 항목명이 같고 문장 틀이 거의 동일하며 수치만 다른 실재 조항을 골랐습니다.
- **정답 근거를 1개 고정했습니다.** 오염이 늘 때 정답 근거까지 사라지면 원인을 가릴 수 없기 때문에,
  L0~L4에서는 정답 조항을 항상 남겨 "오염에 낚였는지"만 측정했습니다.
- **4분류로 채점했습니다.** 정답/기권/오답에 **근거초과**(핵심은 맞지만 근거 밖 내용을 덧붙임)를 더했습니다.
  3분류였다면 설명형의 근거초과 27.7% → 6.1% 개선이 통째로 보이지 않았을 것입니다.
- **LLM 판정을 단독으로 믿지 않았습니다.** 같은 데이터에 관대한 기준은 11.4%, 엄격한 기준은 52.8%를
  내놓았습니다. 오염 조항의 고유 수치가 답변에 들어갔는지 문자열로 직접 확인하는 절차를 병행했습니다.
- **결함 문항을 걸러냈습니다.** 팀원 원문 검수로 오염 취약성이 아닌 다른 것을 재고 있던 3문항을
  발견해 제외했습니다. 제외 전후로 부분 오염 오답률이 2.8% → 0.7%로 바뀌었습니다.

## 앱

방향 전환 이전에 개발한 Streamlit 데모입니다.
질문을 넣으면 LLM 답변을 생성하고, 근거 문서를 검색해 의미 유사도로 대조한 뒤
**Safe / Warning / High Risk**로 표시합니다.

---

## 기술 스택

- **Python** · ChromaDB(직접 사용, LangChain 미사용) · sentence-transformers `jhgan/ko-sroberta-multitask`
- **LLM** GPT-4o-mini — 생성 `temperature=0.7`, 판정 `temperature=0`
- **UI** Streamlit

ChromaDB를 프레임워크 없이 직접 쓴 이유는 오염 검색처럼 비표준적인 검색 로직에
세밀한 제어가 필요했기 때문입니다.
